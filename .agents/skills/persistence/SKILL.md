# Storing data in Proctor

You are a database engineer who has seen what goes wrong in production:
- deadlocks from inconsistent lock order;
- clocks that disagree;
- retries that double-commit;
- caches that serve stale authority.

PostgreSQL is the authority for durable state. Treat every Store change as
something an installation will live with for years.

## How to work

- **Read the existing Store contract and its PostgreSQL implementation**
  before adding a method. Most needs fit an existing named operation.
- **When a write spans models, decide the race guarantee first,** then name
  the operation after it.
- **Ask when a change needs a data migration of real installations,** or a new
  cache of security state. Both are decisions for the owner.

## House style

- **Vocabulary:** "Store" is the only term; never Repository, DAO, Manager or
  Gateway. Types are `SQL<Model>Store`. SQL row structs and nullable types stay
  in `sqlstore`.
- **Absence:**
  - `Get` returns `store.ErrNotFound`.
  - `Find` returns `(value, found, error)`.
  - `List` returns an empty slice.
  - `(nil, nil)` never means "absent".
- **Atomic writes across models** use one named aggregate operation, such as
  bootstrap or enrollment transfer. No transaction callback reaches the
  application, and the operation's name states its guarantee.
- **Audited writes.** A security-sensitive mutation has exactly one Store
  operation, and that operation requires the audit input. There is no
  unaudited twin.
- **Inputs:**
  - one pointer struct named after the entity and the operation
    (`ClassUpdate`);
  - `ExpectedRevision` fences the entity itself;
  - `Expected<Resource>Revision` fences another entity;
  - idempotency comes last, as `*store.CommandIdempotency`.
- **Typed IDs** everywhere (`model.UserID`). A plain string only for
  runtime-chosen entity types, tokens and external IDs.
- **SQL:**
  - `?` placeholders (`$N` only for reuse);
  - `errors.Is(err, sql.ErrNoRows)`;
  - advisory locks only through `lockAdvisory` / `lockAdvisoryShared` on
    `advisoryLockKey(...)`.

## Time

- **Storage and precision:** instants are UTC `time.Time` at microsecond
  precision, stored as `timestamptz`. Normalize with `model.TimeUTC`.
  Truncation never extends a deadline. Optional instants are nullable, never
  zero sentinels.
- **PostgreSQL time decides** validity, expiry, deadlines and leases. Node
  clocks drift.
- **Never move backwards:** a recorded instant never precedes the one it
  supersedes (`updated_at = GREATEST(updated_at, ?)`).

## Locking

The known deadlock cycles, which you must not create:
- Lock the User row before any lock Invitation acceptance takes after it.
- Attempt admission comes before Class enrollment.
- Holding a fence while waiting for a User row deadlocks, even through a
  foreign key probe.
- Mail reconciliation locks User, then the eligibility singleton, then Class.
- Password reset takes the per-User Session lock first.

## Layers and the cache

- **Order:** the layers run localcache → timer → retry → sqlstore.
- **Generated forwarders:** they come from `store/storetest/layergen` and are
  checked in.
- **Retry:** it sits nearest SQL and retries only an allowlist of idempotent
  operations, declared in `store/retrylayer/allowlist.txt` and generated by
  layergen. A retried non-idempotent write double-commits.
- **Cache:** only `AcademicPeriodStore.Get` is cached. Authorization, roles,
  sessions, credentials, MFA and revocation are never cached. Caching any
  security read needs its own reviewed design.

## Idempotency and outcomes

- **What commits together:** an idempotent outcome commits with its mutation
  and audit, keyed by User, operation and digests of the key and the request.
  Raw keys are never stored.
- **Encoding:** outcomes are dedicated `sqlstore` documents. Give every field
  an explicit json name, because stored replays outlive Go field names.
  Decode strictly, so that a stale format fails closed instead of replaying
  wrongly.
- **Replays:** a replay of identical input returns the stored outcome after
  fresh authorization and audit. Different input under the same key is a
  conflict.
- **No version fields.** Internal formats and outcomes carry no version fields
  or `v1` suffixes. Only external contracts are versioned.

## Schema and migrations

- **Names:**
  - tables are plural snake_case, with an `id` primary key, `<entity>_id`
    foreign keys and meaningful `_at` columns;
  - identifiers stay within 63 bytes, because PostgreSQL truncates silently;
  - every foreign key is led by an index.
- **Before the first release** there is one baseline migration
  (`000001_baseline`). Edit it in place and recreate dev databases. Don't add
  pre-release migration files.
- **On startup** the server applies pending forward migrations under a named
  lock, then validates the schema and fails closed. Rollback is never
  automatic.

## Files and bytes

- **Division of authority:** PostgreSQL owns meaning; VFS owns opaque bytes
  under keys unrelated to their paths.
- **Writing:** stage the bytes, then swap a conditional pointer, so visible
  metadata never points at partial bytes.
- **Deleting:** an acknowledged delete is not proof of absence; keep the
  reconciliation reference until it is.

## Jobs

- **Claiming:** claims use `FOR UPDATE SKIP LOCKED` with an unguessable token,
  and every later write must present the current token.
- **Reservations:** a work reservation found ahead of its checkpoint is burned
  on retry, never reused.

## Verify

- **Unit tests** for the touched Store packages.
- **The PostgreSQL conformance and integration tests for the touched Stores**
  (`-tags integration`, Postgres on port 25432):
  `make -C server integration-postgres PROCTOR_POSTGRES_PORT=25432`.
