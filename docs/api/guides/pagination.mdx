# Pagination

List operations return an object with an `items` array, which is never
null. When there are more results, the object also has a `next_cursor`
value.

```json
{
  "items": [
    {
      "id": "01J7YQ4G6V2CKBYZG83K31T6QA",
      "name": "Faculty of Science"
    }
  ],
  "next_cursor": "djE6MDFKN1lRNEc2VjJDS0JZWkc4M0szMVQ2UUE"
}
```

The cursor is opaque and versioned, and it belongs to one exact query. Never
decode it, change it or build your own, and don't rely on what it contains.

## Page through a collection

1. Send the first request with the filters, ordering and `limit` you want.
2. Process every element of `items`. An empty collection is `"items": []`,
   not `null` and not a missing field.
3. If `next_cursor` is present, send the same query again with that exact
   value as `cursor`.
4. Stop when there is no `next_cursor`.

```bash
curl --get \
  --url https://proctor.example.edu/api/v1/academic-units \
  --header 'Authorization: Bearer <token>' \
  --data-urlencode 'limit=50' \
  --data-urlencode 'cursor=<next-cursor-from-previous-response>'
```

You can't change a filter, the order or the scope and keep using the same
cursor. Start a new pass through the collection instead. When you add a
cursor to a URL, URL-encode it.

Keyset pagination is built for collections that may change while you page
through them. It doesn't promise a frozen snapshot, unless the endpoint says
so explicitly. If you reconcile stored state from a collection, make your
processing idempotent.

## Totals on the first page

Some collections also report `total` and `total_is_lower_bound` on the first
page, the one you read without a `cursor`. These are the User directory,
Invitations, Jobs, audit Events, mail deliveries and the current User's own
audit history.

The total counts every item, across all pages, that matches the same filters
and that the caller can see. It is exact below 10,000. At 10,000 Proctor
stops counting and sets `total_is_lower_bound` to `true`. Later pages carry
neither field, so keep the values from the first page.

A total tells you the size, not your position. There is no offset paging,
and items may change while you page through them.

## Search returns one page

`GET /api/v1/search` uses the same `items` envelope but never continues. It
returns at most `limit` matches of each type you ask for. So `next_cursor` is
always absent, and Proctor rejects a `cursor` parameter. To see more results
of one type, use that type's own list operation with its filters and cursor.
