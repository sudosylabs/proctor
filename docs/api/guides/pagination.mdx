# Pagination

List operations return a response object with a non-null `items` array and,
when more results are available, a `next_cursor` value.

```json
{
  "items": [
    {
      "id": "01J7YQ4G6V2CKBYZG83K31T6QA",
      "name": "Faculty of Science"
    }
  ],
  "next_cursor": "djE6MDFKN1lRNEc2VjJDS0JZWkc4M0szMVQ2UUE"
}
```

The cursor is opaque, versioned, and tied to a canonical query. Never decode,
modify, synthesize, or persist assumptions about its contents.

## Traverse a Collection

1. Send the first request with the desired filters, ordering, and `limit`.
2. Process every element of `items`. An empty collection is `"items": []`, not
   `null` and not a missing field.
3. If `next_cursor` is present, repeat the same query and add that exact value
   as `cursor`.
4. Stop when `next_cursor` is absent.

```bash
curl --get \
  --url https://proctor.example.edu/api/v1/academic-units \
  --header 'Authorization: Bearer <token>' \
  --data-urlencode 'limit=50' \
  --data-urlencode 'cursor=<next-cursor-from-previous-response>'
```

Changing a filter, order, or scope while reusing a cursor is invalid. Start a
new traversal instead. Do not concatenate cursor values into a URL without URL
encoding them.

Keyset pagination is designed for collections that may change during
traversal. It does not promise a transactionally frozen snapshot unless the
individual endpoint explicitly says so. Consumers that reconcile durable
state should make their processing idempotent.

## First-Page Totals

Some collections also report `total` and `total_is_lower_bound` on the first
page, the one read without a `cursor`: the User directory, Invitations, Jobs,
audit Events, mail deliveries, and the current User's own audit history. The
total counts every item the same filters and the caller's visibility match
across all pages. It is exact below 10,000; at 10,000 counting stops and
`total_is_lower_bound` is `true`. Later pages carry neither member, so keep the
first page's values. A total is a size hint, not a position: there is no
offset paging, and items may change while you traverse.

## Search Is One Bounded Page

`GET /api/v1/search` uses the same `items` envelope but never continues. It
returns at most `limit` matches of each requested type, so `next_cursor` is
always absent and a `cursor` parameter is rejected. To see more results of one
type, use that type's own list operation with its filters and cursor.
