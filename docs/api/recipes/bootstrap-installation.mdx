# Bootstrap an installation

You bootstrap an installation once. The call creates the Institution, the
first administrator account and the permissions needed to set up everything
else.

## 1. Check whether the installation is bootstrapped

Call <Link to="/api/reference/get-installation-status">Get installation bootstrap status</Link>
without credentials. Carry on only if the response says the installation is
not bootstrapped yet.

## 2. Send the bootstrap secret once

Get the bootstrap secret from the operator through the channel they control
for the installation. Don't put it in a URL, shell history, source file or
support log.

```bash
curl --request POST \
  --url https://proctor.example.edu/api/v1/bootstrap \
  --header 'Content-Type: application/json' \
  --data '{
    "institution": {
      "name": "northbridge-university",
      "display_name": "Northbridge University",
      "description": "Examination services"
    },
    "administrator": {
      "username": "initial-admin",
      "email": "initial-admin@example.edu",
      "display_name": "Initial Administrator",
      "locale": "en",
      "timezone": "Europe/Paris"
    },
    "password": "<strong-one-time-bootstrap-password>",
    "bootstrap_secret": "<operator-provided-bootstrap-secret>"
  }'
```

See <Link to="/api/reference/bootstrap-installation">Bootstrap installation</Link>
for the current password, locale and field rules. The example values are made
up.

## 3. Sign in normally

Once bootstrap succeeds, remove the bootstrap secret from your client's memory.
Then call <Link to="/api/reference/login">Login</Link> to start a normal
interactive Session for the administrator. You can't use bootstrap to sign in
again.

## 4. Check the result and carry on

Read the bootstrap status again, then fetch
<Link to="/api/reference/get-institution">the Institution</Link> with the new
Session. Next, follow the [academic structure recipe](./academic-structure.mdx),
and set up the admission policy by running a preflight before you replace it.

If two bootstrap requests race, only one can succeed. A response saying the
installation is already bootstrapped is final. Don't retry with a different
secret.

## 5. Make the first administrator safe

Bootstrap leaves the administrator's email unverified, because holding a
deployment secret doesn't prove someone controls the mailbox. Using the normal
account calls:

1. Verify the mailbox.
2. Test transactional mail delivery.
3. Configure an external provider in the deployment and turn it on in the
   Access Policy.
4. Connect the provider's immutable identity to the administrator on purpose.
5. Add a second administrator who has their own working sign-in method.
6. Run a preflight before any change that turns off local login.

The Access Policy and the transaction that disables Users both refuse to remove
the last way an active system administrator can sign in. Don't make that
refusal your only recovery plan. <Link to="/reference/command-line/">Host recovery</Link>
is an offline procedure for operators. Password recovery and the separate MFA
reset command never create a Session. After an MFA reset, the person must give
fresh primary proof and enroll again before normal access returns.
