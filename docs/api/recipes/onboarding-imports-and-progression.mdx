# Run onboarding imports and progression

The CSV import keeps reading an untrusted file apart from making lasting
changes. It runs in this order: upload, background checks, a preview that
doesn't change, an explicit commit, row-by-row execution and a report that
Proctor keeps.

<GovernedFigure asset="onboarding-import-timeline" />

## 1. Upload for one mode and scope

POST `text/csv` to <Link to="/api/reference/upload-onboarding-import">Upload Onboarding Import</Link>
with `mode`, `scope_type` and `scope_id`. Include `role_id` only for a mode that
grants a Role. You can pass `file_name` to record the base name of the file you
uploaded. Reads and lists return it as `file_name`.

Check the 10 MiB and 50,000-row limits before you upload, but treat the
server's checks as final.

The accepted response names the import and the Job that checks it. It doesn't
mean any row has changed anything yet.

## 2. Wait for the preview

Poll <Link to="/api/reference/get-onboarding-import">Get Onboarding Import</Link>,
or watch the generic Job. Don't read import rows from the Job payload.

<Link to="/api/reference/list-onboarding-imports">List Onboarding Imports</Link>
finds imports again, newest first. You can filter it by repeating `state`
values. It shows exactly the imports you could read one by one, and returns
summaries without rows. Student progressions don't appear in this list.

When the checks finish, keep the preview digest and review the normalized
results. Unknown headers, duplicate rows in a package, standard names that
don't resolve, rows that reach outside the scope and invalid Unicode are
failures you must review. Don't hide them as warnings.

## 3. Commit the exact preview

Call <Link to="/api/reference/commit-onboarding-import">Commit Onboarding Import</Link>
with the exact preview identity and digest, the documented commit mode and an
`Idempotency-Key`. One preview creates at most one execution Job. Reusing the
key with a different mode or preview is a conflict.

As it runs, Proctor checks the current permissions and target state for every
row. A Job doesn't prove permission. If the requester loses permission partway
through, the remaining rows stop, and the rows already done keep their results.

## 4. Cancel or recover

<Link to="/api/reference/cancel-onboarding-import">Cancel Onboarding Import</Link>
stops new rows from starting. A row that is committing when you cancel still
finishes, so the final result can include successes after you asked to cancel.

Call <Link to="/api/reference/download-onboarding-import-report">Download Onboarding Import report</Link>
after Proctor checks your permission again. The CSV is safe from spreadsheet
formulas, but treat every cell as untrusted text anyway. To undo a row that
succeeded but shouldn't have, use its normal end, revoke or replace call.

## 5. Move students on with a separate preview

Call <Link to="/api/reference/dry-run-student-progression">Dry-run Student Progression</Link>
with the exact source and destination Period and Class IDs, and `effective_at`.
Review the preview, which doesn't change. Then call
<Link to="/api/reference/commit-student-progression">Commit Student Progression</Link>
with the expected preview and the idempotency details.

<Link to="/api/reference/list-student-progressions">List Student Progressions</Link>
finds progressions again, newest first. You can filter by repeating `state`
values and by exact source or destination Period and Class IDs. It shows a
progression only when your progression permissions cover both of its Classes.
Each entry names both Classes, and the first page reports a `total`.

Watch the progression with
<Link to="/api/reference/get-student-progression">Get Student Progression</Link>.
Call <Link to="/api/reference/cancel-student-progression">Cancel Student Progression</Link>
to stop moving more students, and download the
<Link to="/api/reference/download-student-progression-report">formula-safe report</Link>.
A transfer within the same Period ends or replaces the membership in one
transaction. Moving to another Period keeps the old history and creates a new
relationship.

## Retries

| Step | What to do if the result is unclear |
| --- | --- |
| upload | Look up the import by its identity if you have it. Otherwise a new upload creates a separate preview. |
| preview | It's read-only. Repeat it with the same filters. |
| commit | Resend only the exact body with the same idempotency key. |
| row failure | Check the public error code and the current target. Never assume earlier rows were rolled back. |
| cancellation | Wait for a final state and download the report. |
| report download | Let Proctor check your permission again and retry the read. This doesn't change the import's result. |
