# Prepare and enter an Attempt

## Check the server and your Desktop build

Start from the Proctor address your Institution gave you. Desktop's discovery
step locks onto that address. Then `system/ping` checks your exact Desktop
release, build, platform, architecture and realtime protocol.

Stop if the server reports maintenance, update required, incompatible server,
unsupported target or revoked build. Don't edit the values Desktop reports to
make it look compatible.

If Desktop doesn't have an active Session tied to its registered key, go
through [Desktop Authorization](../account/desktop-authorization.mdx) first.
The private key stays inside Desktop, and every protected request carries a
fresh DPoP proof.

## Use Candidate Exam Activity

Candidate Exam Activity is the list that tells you which Exams you can open
and what you can do with each one, and the server is in charge of it. Only
choose an action the server is currently showing you.

A Sitting can appear there before you have an Attempt. Proctor creates your
one Ready Attempt the first time you are allowed to enter. If you never enter,
Proctor doesn't create an Attempt for you.

## What Proctor checks when you enter

Each time you enter, Proctor checks again that:

- you are currently a member of the exact Class;
- the Sitting is in the right state, and its current Revision is selected;
- Desktop has a compatible registered key and an active Desktop Session;
- the Session lock that allows only one unresolved Attempt per User is
  respected;
- Desktop's runtime state is acceptable, and it supports your settings;
- the Attempt is Ready, rather than finished or blocked.

The first time you are let in, Proctor starts one active Participation
generation. It also creates one Connection, tied to that exact Desktop Session
and its registered key. A continuity credential proves that this generation is
yours. It must only ever be held in Desktop's protected memory and in
sensitive request headers. It must never appear in URLs, logs, support
messages or browser storage.

## Your Attempt settings are fixed when you enter

When you are let in, Proctor fixes one Attempt Configuration for the rest of
your Attempt. It is built from your personal settings and from the list of
settings your Desktop build supports. It includes only approved preferences
that both sides understand, for accessibility, appearance, the editor, motion,
announcements, the cursor and keyboard commands. Hidden settings and the
versions of the settings list are kept only as a record of where the
configuration came from.

Reconnecting, or being allowed back in, doesn't rebuild it. If Desktop can't
support the configuration's list of settings, Proctor leaves your Attempt
Ready rather than quietly dropping your preferences.
