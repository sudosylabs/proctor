# Submit safely and get past blocks

When you choose to submit, Proctor seals only the work the server has
confirmed and that is fully in sync. Desktop can offer you the submit option
only when the current runtime allows it and every final check agrees.

## Checks that must agree before you submit

The submit request names:

- your current Participation and its generation;
- the current Revision Desktop expects;
- the last Workspace Cursor the server confirmed;
- the last Focus Loss sequence number;
- the final accounting for Browser Activity.

It also needs your DPoP-bound Session, your continuity credential and an open
current Connection.

Browser Activity is reported as exactly one of these:

- `not_applicable`, only when this Attempt doesn't collect Browser Activity;
- `complete`, with the current final source and sequence number;
- `gapped`, with a short, honest reason.

An honest gap is recorded as a discrepancy, with where it came from, and it
doesn't have to stop your work being sealed. Never report `not_applicable` to
avoid collection that is switched on.

## Common blocks and what to do

| Block | What to do |
| --- | --- |
| Sitting paused | Keep secure renewal and any permitted reporting running, and wait for the Sitting to resume. |
| Correction acknowledgement required | Read the oldest notice, acknowledge its exact Revision, then fetch the Exam view again. |
| Workspace cursor conflict | Catch up with the ordered list of Workspace changes, or reload the full list of files. |
| Focus Loss or Browser Activity sequence conflict | Send or catch up the missing final accounting. Don't lower the sequence number to get past the check. |
| Reconnecting | Renew and reconnect before your exclusive lease expires. |
| Suspended | Ask an Exam Manager to review and let you back in. Entering again will start a new generation. |
| Scheduled deadline reached | Stop making changes. Closing the Sitting takes care of sealing your work. |

## Submitting ends your Attempt

When you submit successfully, Proctor does all of this in one step: it creates
one Submission that can never change, marks the Attempt Submitted, ends your
Participation, and gives you a receipt that is safe for you to see.

If you need to retry, send exactly the same body with the same idempotency
key, but with a fresh DPoP proof. You can't reopen an Attempt or submit it
again.

An authorized Manager can end an unfinished Attempt. That seals the last
Workspace the server confirmed, recorded as `manager_ended_attempt`. When a
Sitting closes, on schedule or early, Proctor seals every unfinished Attempt
that was created, recorded as `sitting_closed`. If you never entered, no
Attempt or Submission is created for you.

You get your receipt and, later, a short result, but only once it has been
released. You can't browse the sealed Workspace or the private integrity
Review.
