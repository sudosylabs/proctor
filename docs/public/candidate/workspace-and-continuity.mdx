# Keep your work and connection confirmed

The server holds the real copy of your Attempt Workspace. Text in your local
editor, a message sent over the WebSocket, or a “saved” indicator doesn't mean
your work is safely stored. It is stored only once the server confirms that
exact change and its Workspace Cursor.

## Working in your Workspace

Proctor copies the Starter Workspace into your own private Attempt Workspace.
Exam Resources stay outside it, and you can read them but not change them.

Workspace paths are case-sensitive, relative POSIX paths, and `.proctor` is
reserved. Proctor rejects links, devices, sockets, paths that climb out of the
Workspace, and deleting a folder that still has things in it.

Each file has a fixed Entry identity, a path that can change, and a current
Content Version, which is an opaque value. Creating, replacing, moving and
deleting a file each check that the file is still in the state you expect, and
each uses an idempotency key that belongs to your Attempt. Once the server
confirms a change, keep the new Content Version and Workspace Cursor.

## Ping, renewal and Connection are different things

<GovernedFigure asset="participation-lease-timeline" />

- A WebSocket ping only checks that the network link is alive.
- Renewing your Participation, with your sign-in proof, shows that this is
  still your generation. Each renewal carries a sequence number that only
  goes up, and extends the generation's lease, which is kept in PostgreSQL.
- A Connection is one lasting record of a network link, and it belongs to
  your current Participation.

Desktop renews at the interval the server gives it. If a sequence number is
sent twice, the server returns the result it already gave. An out-of-date
sequence number can't extend the lease. If you reconnect quickly, before the
lease expires, you may keep the same generation.

When the lease expires, the generation is shut off for good. The server
closes the Connection, records neutral Connection Loss evidence, and suspends
the Attempt.

One failed request or ping is not Connection Loss. A confirmed lease expiry
is. The message you see should say that your secure connection couldn't be
renewed. It shouldn't accuse you of anything, or use internal words like
lease or generation.

## Getting back on track after an interruption

After you reconnect successfully, Desktop fetches the Exam view again and
catches up with the ordered list of Workspace changes since the last
confirmed cursor. If the history doesn't go back far enough, Desktop replaces
its local copy with a complete list of files from the server. It must never
push unconfirmed local files over the copy the server holds.

After the lease expires, after you are Kicked, or after an automatic
Suspension, only an authorized Manager can allow you back in for that exact
episode. Entering again creates a new Participation generation. Old
credentials, sequence numbers and Connections stay shut off. You keep the
same Attempt, Workspace, configuration, Flags and evidence.
