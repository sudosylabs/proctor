# Change a reusable Go module

`packages/cache`, `packages/mail` and `packages/vfs` are separate Go modules.
Their exported contracts must stay useful to a program that doesn't import the
Proctor server. They must not give portable operations a meaning that only
makes sense in Proctor.

## Pick the right module

### Cache

The cache module covers encoded memory and Redis caching, key validation, TTL
normalization, conditional writes, counters, capabilities, and a conformance
suite that every backend reuses.

It doesn't cover durable state, authorization, deciding what may be cached,
namespaces, deleting by broad prefix, or distributed locking.

[Read the cache contract](https://github.com/sudosylabs/Proctor/blob/main/packages/cache/README.md).

### Mail

The mail module covers messages that don't depend on a transport, validation,
MIME composition, SMTP security, delivery with limits, and a portable way to
classify delivery outcomes.

It doesn't cover Proctor templates, recipients, localization, queueing, retry,
rate limits, or provider webhooks.

[Read the mail contract](https://github.com/sudosylabs/Proctor/blob/main/packages/mail/README.md).

### VFS

The VFS module covers portable streaming file operations, normalized relative
paths, opaque conditional revisions, range reads, listing, capabilities, and
the memory, local and S3-compatible backends.

It doesn't cover Users, Exams, authorization, retention, metadata, object keys,
or Workspace policy.

[Read the VFS contract](https://github.com/sudosylabs/Proctor/blob/main/packages/vfs/README.md).

## Change the contract safely

1. Describe the portable behavior, and what is explicitly out of scope, in the
   module README.
2. Change the core interface only when every conforming backend can provide
   the guarantee. When only some backends can, add a narrow optional
   capability instead.
3. Add the behavior to the shared conformance suite before the adapter work,
   or with it.
4. Keep errors portable, so callers can match them with `errors.Is` or
   `errors.As`.
5. Test cancellation, limits, ownership and concurrency, not only the happy
   path.
6. Update the server's use of the module separately, through the server's own
   narrow contract.

An adapter owns the protocol details. The application that uses it owns the
policy. For example, the Redis adapter can implement an atomic counter, but the
Proctor server decides what to count, and whether it must fail closed when the
counter is unavailable.

## Run each module on its own

For cache:

```sh
make -C packages/cache check
make -C packages/cache conformance-redis
```

For mail:

```sh
make -C packages/mail check
make -C packages/mail conformance-smtp
```

For VFS:

```sh
cd packages/vfs
GOWORK=off go test ./...
GOWORK=off go test -race ./...
GOWORK=off go vet ./...
GOWORK=off go build ./...
```

The S3-compatible VFS conformance tests and the server's file content
integration tests run from the server integration target:

```sh
make -C server integration-s3
```

After you change a reusable module, or anything that spans modules, run all
four modules without the Go workspace:

```sh
make independent-modules
```

## Add a backend

A new backend must:

- depend only on the module's portable contract and the library it wraps;
- report its optional capabilities explicitly;
- pass the shared conformance suite;
- document its configuration, and who owns any client passed into it;
- never log values, credentials, message content, file content, or backend
  error details that aren't safe to show;
- keep its cancellation, size, timeout and cleanup behavior when something
  fails.

Don't add an adapter only so the set looks complete. It needs a real consumer,
and a deployment or test that actually runs it.

## Respect the license boundary

The reusable modules are licensed Apache-2.0. The server and webapp together
are AGPL-3.0-only. Don't move server code into a reusable module. Don't copy
AGPL, source-available or commercial upstream code into `packages`.

If you adapt upstream code directly or substantially, keep the notices it
requires. Record the exact repository, revision, path and license, and what
kind of adaptation you made. Borrowing an idea is not permission to copy how
it was written.

## Compatibility

All three modules are still before v1, so their exported APIs can change. Each
change still has a cost. Update every consumer in the repository, the
conformance suite, the examples and the README in the same change.
