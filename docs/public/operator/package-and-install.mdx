# Verify and install a package

A Proctor deployment is one matched set of files: the server binary, the hosted
web application, the configuration example, legal notices, deployment examples
and the build identity. Don't combine a binary and a web application from
different builds.

## Build from source

From a repository checkout you have reviewed, run:

```sh
make package-verify
make dist
make container
```

- `package-verify` assembles the directory for the current platform. It checks
  the executable, the hosted build metadata, the configuration example, the
  systemd unit and the source commit.
- `dist` creates reproducible Linux amd64 and arm64 archives, plus
  `SHA256SUMS`.
- `container` builds the minimal runtime image, which runs as a non-root user.

These commands prove that the repository packages correctly. They don't turn
any checkout into a supported release.

## Verify a release you received

1. Get the archive or image, and its checksum or manifest, through the release
   channel you chose.
2. Check the archive's SHA-256 before you extract it. For an image, select it
   by tag and digest, not by a tag alone, since a tag can move.
3. Run `proctor version --json`. Keep the version, commit, build time and Go
   version in your deployment records.
4. Check that `BUILD_METADATA` and `webapp/dist/webapp-build.json` belong to
   the same commit as the binary.
5. Copy the configuration example. Never edit the extracted example in place
   and use it as your active file with secrets in it.

At startup, Proctor checks the hosted build identity. If it doesn't match the
binary, the server stops before it becomes ready.

## Install files the service can't change

For the systemd layout in the repository, extract the release to
`/opt/proctor` and keep it owned by root. Run the service as the dedicated
`proctor` user. Keep configuration you change in `/etc/proctor`, state in
`/var/lib/proctor`, and log files in `/var/log/proctor`.

Don't run the service from a source checkout it can write to. Don't let the
service account replace its own executable or hosted application. To deploy a
new version, install another complete matched set and restart, as a planned
and reviewed change.
