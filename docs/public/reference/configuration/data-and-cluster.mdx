# Data and cluster settings

PostgreSQL holds the lasting record. Cache entries and cluster messages are
disposable. If either is lost, Proctor must be able to rebuild correct
behavior from what PostgreSQL holds. You need to restart the process after
you change anything on this page.

## PostgreSQL

| Path and default | What it does and accepted values |
| --- | --- |
| `Database.DataSource`<br />Default: `postgres://proctor:proctor@127.0.0.1:15432/proctor?sslmode=disable` | The PostgreSQL connection URL. It must use the `postgres` scheme and include both a host and a database name. Treat any credentials in it as secrets. The default is for development only. |
| `Database.MaxOpenConnections`<br />Default: `40` | The most connections this node's main pool keeps open. Must be at least `2`, because migrations hold a lock on their own connection while ordinary work continues. |
| `Database.MaxIdleConnections`<br />Default: `40` | The most idle connections this node keeps. Must be between half of `MaxOpenConnections` and `MaxOpenConnections`. A lower limit makes the pool close and reopen connections on every burst of work, and each new connection costs PostgreSQL a backend start and an authentication. |
| `Database.ConnectionMaxLifetime`<br />Default: `30m` | The longest a pooled connection lives. Must be greater than zero. |
| `Database.ConnectionMaxIdleTime`<br />Default: `10m` | The longest a pooled connection can stay idle. Must be greater than zero. |
| `Database.ControlConnections`<br />Default: `2` | The size of a second pool that stays open and serves only the serving-node lease, so ordinary load can't delay the renewal that keeps this node serving. Must be between `2` and `4`. |
| `Database.QueryTimeout`<br />Default: `10s` | The default deadline for ordinary database operations, when the caller doesn't set a shorter one. Must be greater than zero. |
| `Database.MigrationTimeout`<br />Default: `1m` | The deadline for migrations at startup, including waiting for their lock. Must be greater than zero. |
| `Database.SlowOperationThreshold`<br />Default: `0s` | Logs a `slow store operation` warning for every store operation that takes at least this long. The warning records only the operation name and how long it took. `0s` turns the warning off. Negative values are rejected. |

Proctor checks the shape of the URL and the limits. It doesn't connect to
PostgreSQL to check them. Put the TLS and credential options your deployment
needs in the query part of the data source.

Each node holds up to `MaxOpenConnections + ControlConnections + 1`
connections: the main pool, the lease pool, and one connection that listens
for queued Jobs. With the defaults that is 43 per node. Multiply by the number
of nodes and keep the result below PostgreSQL's `max_connections`, minus the
`superuser_reserved_connections` and whatever you keep back for
administration and backups. Three nodes with the defaults need 129, so the
PostgreSQL default of 100 is too low. Either raise `max_connections` or lower
`MaxOpenConnections` and `MaxIdleConnections` together.

## Disposable cache

| Path and default | What it does and accepted values |
| --- | --- |
| `Cache.Backend`<br />Default: `memory` | Which cache to use: `memory` for one process, or `redis` for disposable state shared across the installation. Memberlist clustering needs `redis`. |
| `Cache.Namespace`<br />Default: `proctor` | A prefix that keeps this installation's cache keys apart. Must be `1` to `128` ASCII letters, numbers, dots, underscores or hyphens. Use a different value for each installation that shares a Redis server. |
| `Cache.Memory.MaxEntries`<br />Default: `100000` | The most entries the `memory` cache keeps. Must be between `1` and `1000000`. |
| `Cache.Memory.MaxBytes`<br />Default: `67108864` (64 MiB) | The most key and encoded value bytes the `memory` cache keeps. Must be between `1048576` and `1073741824`. The cache's own overhead comes on top. |
| `Cache.Memory.MaxCounters`<br />Default: `100000` | The most sign-in rate limit counters the `memory` cache keeps live, counted separately from the entry and byte limits. Proctor never evicts a counter to make room, so a flood of new usernames can't wipe out another account's limit. While every slot holds an open window, Proctor refuses new sign-in and recovery attempts as temporarily unavailable until windows close. Must be between `1` and `1000000`. |
| `Cache.Redis.Addresses[]`<br />Default: `127.0.0.1:6379` | One or more Redis addresses for the `redis` cache. Each entry must be `host:port`. You need at least one. |
| `Cache.Redis.Username`<br />Default: empty | The Redis ACL username. If you use one, treat it as a credential. |
| `Cache.Redis.Password`<br />Default: empty | The Redis password. It is a secret, so set it through a protected environment override if you can. |
| `Cache.Redis.Database`<br />Default: `0` | The Redis database number. Must be zero or greater. Rely on the namespace, not this number, to keep installations apart. |
| `Cache.Redis.TLS`<br />Default: `false` | Turns on TLS for Redis connections. |
| `Cache.Redis.ConnectTimeout`<br />Default: `5s` | The longest Proctor waits to connect to Redis. Must be greater than zero. |

Proctor checks only the fields for the cache you choose. Keep the other block
in a complete file anyway, so a reviewer can see the change if you switch
caches later. Redis is still disposable. Never treat it as the only copy of
data the application needs to keep.

## Cluster identity and transport

| Path and default | What it does and accepted values |
| --- | --- |
| `Cluster.Backend`<br />Default: `local` | How nodes talk to each other: `local` for a single node, or `memberlist` for an installation with several nodes. |
| `Cluster.NodeID`<br />Default: `local` | A stable name for this process. Must be `1` to `128` ASCII letters, numbers, dots, underscores or hyphens. Every node that runs at the same time needs its own stable ID. |
| `Cluster.Memberlist.BindAddress`<br />Default: `127.0.0.1:7946` | The local address that receives Memberlist traffic. Must be `host:port` with a port from `1` to `65535`. A public or unspecified address needs you to set `AllowPublicBind` as well. |
| `Cluster.Memberlist.AdvertiseAddress`<br />Default: `127.0.0.1:7946` | The address other nodes use to reach this one. Must be `host:port` with a port from `1` to `65535`. It should resolve to the same place from every peer. |
| `Cluster.Memberlist.EncryptionKey`<br />Default: empty | The primary key that encrypts Memberlist traffic. Required with the `memberlist` backend. It must be standard base64 that decodes to `16`, `24` or `32` bytes. Secret. |
| `Cluster.Memberlist.DecryptionKeys[]`<br />Default: empty list | Up to eight unique older Memberlist keys that Proctor still accepts during a rotation. Each follows the same base64 and length rules, and must differ from the primary. |
| `Cluster.Memberlist.SeedAddresses[]`<br />Default: empty list | Up to `32` `host:port` peers that a node contacts to join the cluster. Entries must be valid, and distinct enough for the layout you plan. |
| `Cluster.Memberlist.DiscoveryTTL`<br />Default: `30s` | How long a discovery record lasts. Must be at least `3s`. |
| `Cluster.Memberlist.DiscoveryHeartbeat`<br />Default: `10s` | How often a node refreshes its discovery record. Must be greater than zero and less than half of `DiscoveryTTL`. |
| `Cluster.Memberlist.AllowPublicBind`<br />Default: `false` | Confirms that you mean to use a public or unspecified bind address. It doesn't make a public gossip listener safe. Restrict access to it at the network edge. |

The `memberlist` backend also needs the Redis cache and a VFS backend other
than local. Every node shares PostgreSQL, Redis, file storage, keys, and the
same cluster configuration. You can't use built-in Let's Encrypt with
Memberlist.

To rotate the Memberlist key, first add the old primary to every node's list
of older keys, then bring in the new primary. Wait until every node has the
change before you remove the old key. Never reuse a Memberlist key for mail or
MFA encryption.
