# Localization and logging settings

Localization sets the language Proctor falls back to for the installation.
Logging sets one or more places where logs go, each with limits. You need to
restart the process after you change localization. Proctor applies a valid
logging configuration after a reload, without a restart.

## Localization

| Path and default | What it does and accepted values |
| --- | --- |
| `Localization.DefaultLocale`<br />Default: `en` | The fallback locale for the whole installation. It must be a language tag with no leading or trailing spaces, no longer than `35` characters. Each part between hyphens must be `1` to `8` letters, and parts after the first can also contain digits. At startup, Proctor also needs a bundled catalog that matches. |

Use a locale that ships with the server. Checking the format can't tell
whether a catalog exists. The localization module checks that when the server
starts.

## Logging pipeline

The logging pipeline cuts down fields that are too large, limits how far its
queues grow, and gives queueing, flushing and shutdown a fixed deadline. You
need at least one target.

| Path and default | What it does and accepted values |
| --- | --- |
| `Log.MaxFieldBytes`<br />Default: `16384` (16 KiB) | The largest encoded size Proctor keeps for one structured field. Must be between `256` and `1048576` bytes. This limit keeps logs safe. It doesn't make it acceptable to log secrets or user content of any size. |
| `Log.QueueSize`<br />Default: `1024` | How many records the shared background queue holds. Must be between `1` and `1048576`. |
| `Log.EnqueueTimeout`<br />Default: `250ms` | The longest Proctor waits to queue a record when the queue is busy. Must be greater than zero and no more than `1m`. |
| `Log.FlushTimeout`<br />Default: `5s` | The deadline when Proctor is asked to flush the pipeline. Must be greater than zero and no more than `1m`. |
| `Log.ShutdownTimeout`<br />Default: `10s` | The deadline for draining and closing logging at shutdown or when Proctor replaces the pipeline. Must be greater than zero and no more than `1m`. |

Bigger queues use more memory, and they can delay when records appear if a
target is slow. If a queue stays under pressure, treat it as a problem with
the output or with capacity. Don't raise every limit without measuring first.

## Log targets

By default there is one console target in readable text. Target names must be
unique. `Type`, `Level` and `Format` values ignore case, but writing them in
lower case keeps the configuration consistent.

| Path and default | What it does and accepted values |
| --- | --- |
| `Log.Targets[].Name`<br />Default: `console` | A stable name for the target, unique in the list. Required. It identifies the output in diagnostics and when you compare configurations. |
| `Log.Targets[].Type`<br />Default: `console` | Where the output goes: `console` or `file`. |
| `Log.Targets[].Level`<br />Default: `info` | The lowest severity written: `trace`, `debug`, `info`, `warn` or `error`. Don't leave the verbose levels on for long without checking what data they expose and how much they write. |
| `Log.Targets[].Format`<br />Default: `text` | How records are written: `text` for people to read, or `json` for log collectors. |
| `Log.Targets[].File`<br />Default: empty | The file a `file` target writes to. Required for file output. It can't contain null or line break characters, and must be empty for `console`. A relative path starts from the process working directory. |
| `Log.Targets[].QueueSize`<br />Default: `256` | How many records this target's background queue holds. Must be between `1` and `1048576`. This stops a slow target from using unlimited memory. |
| `Log.Targets[].MaxSizeMB`<br />Default: `0` for console | The size, in MiB, at which a `file` target starts a new file. File targets need a value between `1` and `10240`. Console output doesn't use it. |
| `Log.Targets[].MaxAgeDays`<br />Default: `0` | The oldest a rotated log file can get before Proctor removes it. For file targets, must be between `0` and `3650`. `0` turns off removal by age. |
| `Log.Targets[].MaxBackups`<br />Default: `0` | The most rotated files Proctor keeps. For file targets, must be between `0` and `10000`. `0` turns off removal by count. |
| `Log.Targets[].Compress`<br />Default: `false` | When `true`, Proctor compresses rotated log files. It has no effect on console output. |

If you collect logs in production, JSON usually keeps fields intact better
than parsing text. Proctor rotates files only for `file` targets. For console
output, your process supervisor or container log pipeline decides how long
logs are kept.

## Changing logging while the server runs

On a reload, Proctor checks the whole configuration file before it builds the
new logging pipeline. If the new logging setup fails, Proctor reports the
error through the logger it already has, rather than acting as if the new
target is working. Check that the target you expect is working after every
change.

Logging settings never loosen the repository's rules on data. Credentials,
secrets, student data, exam answers, and user content of unlimited size don't
belong in ordinary logs.
