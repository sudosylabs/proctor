# Mail and file settings

Mail and file storage are separate jobs. SMTP sends transactional messages.
The VFS stores file bytes, and PostgreSQL keeps the details about each file.
You need to restart the process after you change anything on this page.

## Mail delivery

| Path and default | What it does and accepted values |
| --- | --- |
| `Mail.Enabled`<br />Default: `false` | Turns on transactional mail. Proctor checks the encryption keys even while mail is off, so a broken key rotation can't go unnoticed. |
| `Mail.Backend`<br />Default: `smtp` | How mail is sent. The only accepted value is `smtp`. |
| `Mail.FromAddress`<br />Default: `no-reply@localhost` | The sender address on the envelope and the message. When mail is on, it must be one plain email address. Use a domain your SMTP service is allowed to send for. |
| `Mail.FromName`<br />Default: `Proctor` | The sender name people see. When mail is on, it can't contain unsafe control characters. |
| `Mail.SupportAddress`<br />Default: empty | The address that message footers tell people to contact with questions, such as an IT service desk. When it is empty, footers tell people to contact the institution by name. If you set it, it must be one plain email address. Proctor also publishes it in public discovery, so hosted pages can show it as the support contact to people who aren't signed in. |
| `Mail.DisplayTimezone`<br />Default: `UTC` | An IANA time zone, such as `Africa/Lagos`, or empty for UTC. Proctor uses it to write dates and times in messages for people who haven't chosen their own time zone. Exam sitting messages are fixed once for every recipient and always use this zone. |
| `Mail.SMTP.Address`<br />Default: `127.0.0.1:1025` | The SMTP server, as `host:port`. The default points to a local mail catcher for development. |
| `Mail.SMTP.ServerName`<br />Default: empty | Overrides the server name Proctor checks the TLS certificate against. Leave it empty only when the SMTP host name is already the right name to check. |
| `Mail.SMTP.LocalName`<br />Default: empty | The name Proctor sends in SMTP `EHLO` or `HELO`. When empty, the transport uses its usual local name. Control characters are rejected. |
| `Mail.SMTP.Security`<br />Default: `none` | How the connection is protected: `none`, `starttls` or `tls`. SMTP with authentication needs `starttls` or `tls`. Use `none` only for local development on a protected machine. |
| `Mail.SMTP.Username`<br />Default: empty | The SMTP username. Required when `Authentication` isn't `none`. |
| `Mail.SMTP.Password`<br />Default: empty | The SMTP password. It is a secret, so set it through a protected environment override if you can. It must be empty when authentication is `none`. |
| `Mail.SMTP.Authentication`<br />Default: `none` | How Proctor signs in to the SMTP server: `none`, `auto`, `plain` or `login`. Any value other than `none` needs a username and an encrypted connection. |
| `Mail.SMTP.Timeout`<br />Default: `10s` | The deadline for SMTP network operations. Must be greater than zero. |
| `Mail.SMTP.MessageIDDomain`<br />Default: `localhost` | The domain Proctor puts in the `Message-ID` values it generates. Must not be empty, and can't contain whitespace, `@` or control characters. Use a stable domain your installation controls. |
| `Mail.SMTP.MaxMessageBytes`<br />Default: `26214400` (25 MiB) | The largest message Proctor sends, once encoded. Must be between `1024` and `104857600` bytes. This is a safety limit. It doesn't mean your SMTP service accepts messages that large. |
| `Mail.SMTP.MaxRecipients`<br />Default: `100` | The most recipients in one send. Must be between `1` and `1000`. |

Turning mail on doesn't mean mail gets delivered. Before production, test with
your real SMTP service: DNS, permission to send for your domain, certificate
trust, relay permissions, the service's size limits, and how retries behave.

## Mail secret encryption

Proctor encrypts the mail secrets it stores with its own keys, separate from
the SMTP credentials. Every application node must have the same keys.

| Path and default | What it does and accepted values |
| --- | --- |
| `Mail.SecretSealing.EncryptionKey`<br />Default: empty | The primary AES-256 key for encrypting new mail secrets. It must be standard base64 that decodes to exactly `32` bytes. Required when mail is on, and whenever you have older keys listed. Secret. |
| `Mail.SecretSealing.DecryptionKeys[]`<br />Default: empty list | Up to eight unique older AES-256 keys that Proctor uses to read older secrets during a rotation. Each is a `32`-byte key in standard base64, and must differ from the primary. |

To rotate the key, add the current primary to `DecryptionKeys` before you
change the primary. Deploy the full set of keys to every node, let older work
finish, and only then remove the retired key. Never reuse these keys for MFA
or Memberlist.

## File storage

| Path and default | What it does and accepted values |
| --- | --- |
| `VFS.Backend`<br />Default: `local` | Where file bytes are stored: `local` or `s3`. A Memberlist cluster can't use `local`, because every node must see the same files. |
| `VFS.Local.Root`<br />Default: `./data` | The root folder for the local backend. Must be a non-empty path with no null byte. A relative path starts from the process working directory. Back up this folder in step with PostgreSQL, using your normal procedures. |
| `VFS.S3.Endpoint`<br />Default: empty | The address of the S3-compatible service. Required for the `s3` backend. It can't contain control characters. Write it in the form the S3 client expects. |
| `VFS.S3.AccessKey`<br />Default: empty | The static S3 access key ID Proctor gives the client. Set it together with its secret, unless the storage service is meant to allow anonymous access. Once filled in, treat it as a credential. |
| `VFS.S3.SecretKey`<br />Default: empty | The S3 secret access key. It is a secret, so use a protected environment override or credentials from your workload's platform if you can. |
| `VFS.S3.SessionToken`<br />Default: empty | The session token for temporary credentials. Secret. Rotate it together with the access credentials it belongs to. |
| `VFS.S3.Bucket`<br />Default: empty | The bucket that holds Proctor's files. Required for `s3`. Must not be empty, and can't contain `/` or control characters. |
| `VFS.S3.Prefix`<br />Default: empty | Optional. A key prefix inside the bucket. It can't contain control characters. Use a separate prefix when you share a bucket. |
| `VFS.S3.Region`<br />Default: empty | The region Proctor gives the S3-compatible client. Whether it can be empty depends on the storage service. |
| `VFS.S3.Secure`<br />Default: `true` | When `true`, Proctor connects to the S3-compatible service securely. Keep it on, except on development infrastructure that you have deliberately isolated. |

Only the VFS backend you choose is used. PostgreSQL holds the details about
each file, and the VFS holds the bytes. Don't treat storage keys as if they
were public file IDs.

## File processing

| Path and default | What it does and accepted values |
| --- | --- |
| `FileContent.MaximumConcurrentOperations`<br />Default: `2` | How many expensive checks and renditions each node runs at once. Must be greater than zero. Raise it only after you measure CPU, memory, storage, and the load on services further down the line. |
