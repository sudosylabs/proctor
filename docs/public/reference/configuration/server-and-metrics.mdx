# Server and metrics settings

These fields control the HTTP server that clients use and the separate
listener that Prometheus scrapes. You need to restart the process after you
change them.

The defaults shown here are the values built into Proctor, and they match the
[complete example](https://github.com/sudosylabs/Proctor/blob/main/server/config/config.example.json).

## File version

| Path and default | What it does and accepted values |
| --- | --- |
| `Version`<br />Default: `1` | The version of the configuration format. Must be `1`. Proctor rejects any other value rather than guessing or quietly migrating it. |

## Public server

| Path and default | What it does and accepted values |
| --- | --- |
| `Server.ListenAddress`<br />Default: `127.0.0.1:8065` | The TCP address for client traffic. Must be `host:port`. Port `0` is allowed so tests can use a temporary port. In production you normally use a fixed port. |
| `Server.PublicURL`<br />Default: `http://localhost:8065` | The address browsers use. Proctor builds every URL it shows outside the server from it. Must be an absolute `http` or `https` URL with a host, and no credentials, query or fragment. The path must be empty or `/`. Built-in TLS needs `https`. |
| `Server.WebappDirectory`<br />Default: `./webapp/dist` | The folder that holds the built webapp Proctor serves. Must be a non-empty path with no null byte. A relative path starts from the process working directory. |
| `Server.ReadHeaderTimeout`<br />Default: `10s` | The longest Proctor waits to read the request headers. Must be greater than zero. |
| `Server.ReadTimeout`<br />Default: `30s` | The longest Proctor waits to read the whole request. For a signed-in streaming upload, Proctor adds the time the route's body limit takes at 64 KiB/s. Must be greater than zero. |
| `Server.WriteTimeout`<br />Default: `30s` | The longest Proctor spends writing a response. For streaming uploads and file downloads, Proctor adds the time their declared size takes at 64 KiB/s. Must be greater than zero. |
| `Server.IdleTimeout`<br />Default: `2m` | The longest a keep-alive connection can sit idle. Must be greater than zero. |
| `Server.ShutdownTimeout`<br />Default: `15s` | One time budget for the whole shutdown, counted from when shutdown starts. It covers draining HTTP, waiting for serving to end, draining Jobs and WebSocket connections, stopping the metrics listener, sending the last spans, and leaving the cluster cleanly. Each step gets only the time left over, so shutdown never takes longer than this, apart from the final log flush. Must be greater than zero. |
| `Server.MaxHeaderBytes`<br />Default: `1048576` (1 MiB) | The largest request headers Proctor accepts. Must be between `1024` and `16777216` bytes. |
| `Server.MaxBodyBytes`<br />Default: `1048576` (1 MiB) | The largest request body Proctor accepts on any route. Individual routes can set lower limits. Must be between `1024` and `104857600` bytes. |
| `Server.TrustedProxies[]`<br />Default: empty list | Reverse proxies whose `X-Forwarded-For` and `X-Request-ID` headers Proctor accepts, as IP addresses or CIDR prefixes. At most 256 entries. When the list is empty, Proctor trusts no proxy. It treats the connecting address as the client and generates every request ID itself. A proxy you list must overwrite any `X-Request-ID` the client sent, because Proctor accepts the value the proxy forwards. |

`PublicURL` is the address clients use. It doesn't set the address Proctor
listens on. When a reverse proxy handles TLS, keep the public URL on `https`,
have Proctor listen on the protected network behind the proxy, and leave
built-in TLS turned off.

List your proxy addresses in `Server.TrustedProxies` so that audit records and
sign-in rate limits see the real client, not the proxy. Proctor uses the
rightmost address in `X-Forwarded-For` that isn't one of your proxies. It
ignores the `Forwarded` header.

## Built-in TLS

| Path and default | What it does and accepted values |
| --- | --- |
| `Server.TLS.Mode`<br />Default: `disabled` | How the client listener handles TLS: `disabled`, `static` or `lets_encrypt`. |
| `Server.TLS.CertificateFile`<br />Default: empty | Path to the PEM certificate chain. Required with `static`. The `disabled` and Let's Encrypt modes ignore it. |
| `Server.TLS.PrivateKeyFile`<br />Default: empty | Path to the PEM private key. Required with `static`. Protect the file as you would any service credential. |
| `Server.TLS.LetsEncrypt.Email`<br />Default: empty | The contact email Proctor gives the ACME account when you choose `lets_encrypt`. |
| `Server.TLS.LetsEncrypt.CacheDirectory`<br />Default: `./data/acme` | Where Proctor keeps ACME certificates so they survive restarts. Must not be empty for `lets_encrypt`. A relative path starts from the process working directory. |
| `Server.TLS.LetsEncrypt.AcceptTermsOfService`<br />Default: `false` | Your explicit acceptance of the Let's Encrypt Subscriber Agreement. Must be `true` for `lets_encrypt`. Proctor never accepts the terms for you. |
| `Server.TLS.ForwardHTTPToHTTPS`<br />Default: `false` | Starts a second, plain HTTP listener for ACME HTTP-01 challenges and redirects to HTTPS. TLS must be turned on. Let's Encrypt needs this set to `true`. |
| `Server.TLS.HTTPListenAddress`<br />Default: `127.0.0.1:8080` | The address of the second HTTP listener. Must use a port from `1` to `65535`, and must differ from `Server.ListenAddress` when forwarding is on. |
| `Server.TLS.StrictTransportSecurityMaxAge`<br />Default: `8760h` (365 days) | The max-age in the `Strict-Transport-Security` header, which Proctor sends on every response while built-in TLS is on. Must be whole seconds from `0` to `17520h`. `0` turns HSTS off. Proctor never sends the header in `disabled` mode, because the proxy that handles TLS is then responsible for HSTS. |

Let's Encrypt works on a single node only, by design. You can't use it with
the Memberlist cluster backend. The host in `PublicURL` must be a lower-case
ASCII fully qualified domain name. It can't be localhost, an IP address or a
single label. The ACME cache must survive process restarts.

In `static` mode, the certificate and private key files must be a matching
pair. In either built-in TLS mode, `Server.PublicURL` must use `https`.

## Metrics listener

| Path and default | What it does and accepted values |
| --- | --- |
| `Metrics.Enabled`<br />Default: `false` | Set to `true` to start the Prometheus metrics listener on this node. |
| `Metrics.ListenAddress`<br />Default: `127.0.0.1:8067` | The address the metrics listener uses. Must be `host:port` with a port from `1` to `65535`. When metrics are on, it must differ from the public address and the HTTP forwarding address. |
| `Metrics.BearerToken`<br />Default: empty | The secret scrapers must send in the `Authorization: Bearer` header. If you set it, it must be `32` to `512` bytes long. A listener that isn't on loopback needs it. |
| `Metrics.TLS.CertificateFile`<br />Default: empty | Path to the PEM certificate chain for the metrics listener. Set the certificate and private key together. |
| `Metrics.TLS.PrivateKeyFile`<br />Default: empty | Path to the PEM private key for the metrics listener. Protect it as you would any service credential. |
| `Metrics.ReadHeaderTimeout`<br />Default: `5s` | The longest Proctor waits to read a scrape request's headers. Must be greater than zero. |
| `Metrics.ReadTimeout`<br />Default: `10s` | The longest Proctor waits to read a scrape request. Must be greater than zero. |
| `Metrics.WriteTimeout`<br />Default: `30s` | The longest Proctor spends writing a scrape response. Must be greater than zero. |
| `Metrics.IdleTimeout`<br />Default: `1m` | The longest a keep-alive connection can sit idle. Must be greater than zero. |
| `Metrics.ShutdownTimeout`<br />Default: `5s` | The most time Proctor allows for stopping the metrics listener. Stopping also ends when the shared `Server.ShutdownTimeout` budget runs out. Must be greater than zero. |
| `Metrics.MaximumConcurrentScrapes`<br />Default: `2` | How many Prometheus scrapes each node serves at once. Must be between `1` and `32`. |
| `Metrics.ProfilingEnabled`<br />Default: `false` | Also serves Go runtime profiles under `/debug/pprof/` on the metrics listener. Needs `Metrics.Enabled` and `Metrics.BearerToken`. |

If the metrics listener is on and listens beyond loopback, you must set both
TLS files and a bearer token. Proctor refuses the configuration otherwise, so
you can't expose metrics without authentication by accident. Store the token
apart from the public server's TLS key, and scrape over HTTPS.

Proctor never serves profiles on the public listener. When profiling is on,
the profiles use the same bearer token as `/metrics`. Proctor never serves the
command-line profile, because process arguments can contain secrets. A CPU
profile or execution trace must finish within `Metrics.WriteTimeout`. Ask for
a `seconds` value below it, or raise the timeout while you investigate.

## Tracing

| Path and default | What it does and accepted values |
| --- | --- |
| `Tracing.Enabled`<br />Default: `false` | Records OpenTelemetry spans for HTTP routes, store operations and Job runs, and sends them over OTLP/HTTP. |
| `Tracing.EndpointURL`<br />Default: `http://127.0.0.1:4318/v1/traces` | The full OTLP/HTTP traces URL, usually a collector on the node or its network. Must be an absolute `http` or `https` URL with no credentials, query or fragment. |
| `Tracing.SampleRatio`<br />Default: `1` | The share of new root traces Proctor records, from `0` to `1`. A request that continues a trace from a trusted proxy follows the proxy's sampling decision. |
| `Tracing.Headers`<br />Default: `{}` | HTTP headers sent with every export. This is usually a hosted backend's API key, such as `x-honeycomb-team` or a Grafana Cloud `Authorization` value. The values are secrets. Proctor hides them when it shows configuration and never logs them. At most 16 headers. Names must be HTTP tokens and unique regardless of case. They can't be headers the transport controls (`Content-Type`, `Content-Encoding`, `Content-Length`, `Host` or hop-by-hop headers). Values must not be empty, must be at most 8192 bytes, and can't contain line breaks or leading or trailing whitespace. Needs an `https` `EndpointURL` unless the collector is on loopback. `PROCTOR_TRACING_HEADERS` replaces the whole map, written in the `OTEL_EXPORTER_OTLP_HEADERS` format, for example `x-honeycomb-team=<key>`. |
| `Tracing.ExportTimeout`<br />Default: `10s` | The deadline for one export request to the collector. Must be positive and at most `1m`. |
| `Tracing.ShutdownTimeout`<br />Default: `5s` | How long Proctor has to send buffered spans at shutdown. Sending also stops when the shared `Server.ShutdownTimeout` budget runs out. Must be positive and at most `1m`. |

Proctor continues an incoming W3C `traceparent` only from an address in
`Server.TrustedProxies`. This is the same rule it uses for request IDs. Any
other client starts a new trace and can't force sampling. Spans never contain
request paths, query strings, credentials, client addresses, User data or
exam content. See [traces](../../operator/health-and-observability.mdx#traces).
