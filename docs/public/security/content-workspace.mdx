# Content, Workspace and Submission security

PostgreSQL decides what a piece of content is and who may access it. The VFS
only stores bytes, without knowing what they mean. Neither the VFS nor any
other outside system can grant access in the application, whether through an
object key, a path or the state of a local filesystem.

## Managed content

Proctor limits the size of an upload before it starts and while it streams in.
It works out the content type from the bytes themselves, and stages the upload
under a private key that can't be guessed. Any required inspection and
renditions finish before a named Store operation marks the metadata Available.

If Proctor can't tell whether a database write succeeded, it keeps the staged
objects. They stay until cleanup, which checks for references, can prove it is
safe to delete them.

A protected download checks permission on the metadata before it opens any
bytes. The response sets an explicit media type, length and ETag, a
`private`, `no-store` cache policy, and `nosniff`. Proctor doesn't hand out
public or signed object-storage URLs.

## Attempt Workspace and Submission

Workspace paths are stored as metadata. They are normalized, limited in
length, case-sensitive and relative, in POSIX form. Proctor refuses path
traversal, links, devices, sockets, and writes by the candidate to `.proctor`.

Every change to a Workspace is checked against all of these, and is refused if
any of them no longer match:

- the current Participation and its generation;
- the credential, Session and Connection;
- the expected entry, path and version;
- the idempotency key for that Attempt.

A Submission records exactly which logical entries and content versions were
acknowledged, without copying the bytes. Exam Managers can inspect a Submission
only after it is sealed, and it can't change after that. They can't read the
live Workspace. Candidates get a safe receipt. They can't browse the sealed
list of files or the files themselves.

## Governed Browser

The governed Browser follows a frozen allowlist, one that can't change. It
records a minimal account of top-level page visits. The content of the pages
never becomes evidence.
